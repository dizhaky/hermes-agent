- **Agent/tool:** Claude Code (remote session), `gitleaks` 8.24.3
- **Repos:** hermes-agent
- **Done:** Closed the security gap the 2026-07-25 daily repo scan reported —
  this repo had **no secret scanning of any kind** (no gitleaks/trufflehog
  workflow, no `.pre-commit-config.yaml`) while shipping 1Password and Bitwarden
  credential-bootstrap paths. `supply-chain-audit.yml` covers attack-pattern
  indicators only (`.pth` files, base64+exec) and is `pull_request`-scoped.
  - `.github/workflows/secret-scan.yml` — gitleaks on every push and PR,
    **diff-scoped** (never rescans history), gitleaks pinned by version *and*
    tarball SHA256, `actions/checkout` SHA-pinned per the repo's pinning policy.
  - `.gitleaks.toml` — custom rules plus a narrow allowlist (below).
  - `AGENTS.md` — a *Secret Scanning* section next to the Dependency Pinning
    Policy, covering what to do when the scan fires. Deliberately **not** added
    to `SECURITY.md` §2: that section documents the runtime trust boundary and
    is careful about what does and does not count as one. A CI hygiene check is
    neither.
- **Two findings worth recording:**
  1. **gitleaks' stock ruleset has no Anthropic rule at all.** A well-formed
     `sk-ant-api03-…` canary passed straight through the default config. For an
     agent framework whose primary job is calling Claude, that is the single
     most likely credential to leak. Added explicit `anthropic-api-key`,
     `anthropic-admin-key`, and `openrouter-api-key` rules — OpenRouter
     otherwise falls to the entropy-based `generic-api-key`, which misses a key
     that appears without a nearby keyword.
  2. **No committed credentials exist in the repo** — but this is now a much
     stronger claim than the one in the 2026-07-25 entry, which rested on a
     narrow pattern grep. A full-tree gitleaks scan surfaced **647 findings in
     tracked files** that the grep missed; every one was triaged and every one
     is benign: ~534 in two vendored upstream unsloth reference docs, the rest
     published OAuth client IDs (each already carrying an in-source comment
     saying why it is non-confidential), gemini-cli's public desktop client
     secret, Discord/Mattermost user and channel IDs in documentation examples,
     and test fixtures.
- **Verification:**
  - Allowlist tuning takes the tracked tree from **647 → 82** findings; all 82
    residual are unmarked placeholder strings inside `tests/`, and none fire in
