- **Done:**
  - **`py/tarslip` — `_install_psutil_android_compat` (`main.py`).**
    `tar.extractall(tmp_path)` with no member validation and no extraction
    filter, on a psutil sdist fetched over the network. The URL is pinned but the
    download's **checksum is never verified**, so a compromised or MITM'd sdist
    could write outside the temp dir via `../` or absolute members. Added the
    same guard `agent/curator_backup.py` already uses — reject traversal members
    up front, then `extractall(..., filter="data")` with a `TypeError` fallback
    for interpreters older than 3.11.4. (The guard was hardened further in the
    second round below — the first version checked names only.)
  - **The sibling copy.** `scripts/install_psutil_android.py:86` had the identical
    unguarded call. Its module docstring says the two copies must be kept in sync
    and removed together, so both are fixed. CodeQL flagged only the `main.py`
    one — its `py/tarslip` query needs a taint path its analysis actually
    traversed, so an equivalent bug in a standalone script went unreported.
  - **`py/incomplete-url-substring-sanitization` — `_infer_stepfun_region`.**
    `if "api.stepfun.com" in normalized` matched by substring, so
    `api.stepfun.com.example.net` inferred `china`. Now parses the host and
    compares exactly. **Impact is cosmetic** — the inferred region only
    pre-selects an entry in an interactive menu, and the endpoint actually used
    comes from `_stepfun_base_url_for_region(selected_region)` off the user's
    explicit choice. Fixed because it is two lines and strictly more correct, not
    because it was exploitable.
- **Second round, after Codex review on PR #156 — two real defects in my own fix:**
  - **The name-only guard was not equivalent to `filter="data"`.** On Python
    3.11.0–3.11.3 (in range for `requires-python = ">=3.11"`) the unfiltered
    fallback runs, and a member with a *clean name* can be a symlink whose
    **target** escapes — `psutil-7.2.2/link -> ../../outside`, then
    `psutil-7.2.2/link/pwned.txt` writes outside the destination through it.
    Reproduced with a working archive before fixing. The guard now resolves link
    targets against the link's own directory and requires containment, and
    refuses non-regular members — both of which `data` also does. Extracted to
    `agent.file_safety.assert_safe_tar_members` so there is one implementation.
  - **`urlparse(...).hostname` raises `ValueError`** on a malformed netloc
    (`https://[foo`). `_infer_stepfun_region` receives unvalidated
    `STEPFUN_BASE_URL` / `model.base_url` values, so my change turned a total
    function partial and would abort provider setup before the region picker —
    a regression against the substring version it replaced. Now catches and
    defaults to `international`.

  shape and therefore the same symlink gap — and it extracts into the **skills**
  directory (executable content) rather than a temp dir, so the gap mattered

- **Third round — merged `origin/main`, and most of this change turned out to be
  superseded.** `main` had refactored the psutil sdist extraction into
  `hermes_cli/psutil_android.prepare_patched_psutil_sdist`, which does not call
  `extractall` at all: it copies file members one at a time with
  `extractfile()` + `copyfileobj()` and refuses every non-file member, so link
  members can't exist in the output. `_install_psutil_android_compat` moved to
  `hermes_cli/update_cmd.py` and calls it; the standalone script imports it too,
  which also retires the duplicated validator. Both psutil-side halves of this
  change are therefore dropped in favour of main's — main's approach is
  structurally better, since it removes the unfiltered fallback rather than
  guarding it. What survives is `assert_safe_tar_members` (still the guard for
  `curator_backup`'s fallback) and the `_infer_stepfun_region` fix.
- **A third real defect, again from Codex review — hardlinks resolve from a
  different base than symlinks.** The guard treated `issym()` and `islnk()`
  identically, resolving both against the link's own directory. That is right
  for a symlink (handed to `os.symlink` verbatim, read by the kernel relative to
  the link) and wrong for a hardlink, which `tarfile` resolves itself against
  the **extraction root** — `TarFile._extract_member` sets
  `tarinfo._link_target = os.path.join(path, tarinfo.linkname)`. So
  `a/b/link -> ../victim` under-resolved to a harmless `a/victim` and passed the
  guard, while `tarfile` linked it to `<root>/../victim`, a file beside the
  destination.
  - **Reproduced end to end before fixing**, not reasoned about: the guard
    accepted the archive, `extractall` produced a link sharing an inode with the
    outside file, and writing through it changed that file's contents. Reachable
    on Python 3.11.0–3.11.3, which is in range for `requires-python = ">=3.11"`.
  - Fixed by picking the base per link type. A test asserts the resulting
    asymmetry directly: the *same* `linkname` is refused as a hardlink and
    allowed as a symlink.
