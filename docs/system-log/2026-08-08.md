- **A third real defect, again from Codex review — hardlinks resolve from a
  different base than symlinks.** The guard treated `issym()` and `islnk()`
  identically, resolving both against the link's own directory. That is right
  for a symlink (handed to `os.symlink` verbatim, read by the kernel relative to
  the link) and wrong for a hardlink, which `tarfile` resolves itself against
  the **extraction root** — `TarFile._extract_member` sets

  `a/b/link -> ../victim` under-resolved to a harmless `a/victim` and passed the
  guard, while `tarfile` linked it to `<root>/../victim`, a file beside the
  destination.

    outside file, and writing through it changed that file's contents. Reachable

    asymmetry directly: the *same* `linkname` is refused as a hardlink and

- **Fourth round — Windows path semantics (Codex P2, real).** The guard parsed
  member names with `PurePosixPath`, but `extractall` builds its destination with

  The cost, recorded rather than hidden — a filename that genuinely contains a
  backslash (legal on POSIX) is now refused. 7 cases; positive control fails

  that this branch changes no JS, TS, JSON, manifests or lockfiles. The actual
  cause is better evidence:

  ```
  Error: Incompatible React versions: react and react-dom must have the exact
  same version.  react: 19.2.8   react-dom: 19.2.7
  ```

  Every workspace `package.json` declares `19.2.7`, but the **root hoisted**
  `node_modules/react` resolves to `19.2.8` while `react-dom` stays at `19.2.7`
  — and `package-lock.json` is byte-identical on `origin/main`, so a root bump
  landed without `react-dom` following. It fails four suites in `web/` alone
  (147 tests still pass; the four failures are all this import-time error).

  Deliberately **not** fixed here, unlike the two one-liners above. Realigning
  needs a regenerated lockfile via `npm install`, which is neither verifiable in
  this sandbox nor a one-line judgment call — whether to pull root react back to
  19.2.7 or push react-dom to 19.2.8 is a dependency-policy decision, and the
  repo has dependabot for exactly this. Worth raising separately, since it
  blocks every JS check repo-wide.
