## 2026-08-01T20:45:00Z — Recover hardening orphaned when PR #106 was closed (Claude Code)

- **Agent/tool:** Claude Code (remote session) + a `fable` subagent for the

- **Repos:** hermes-agent
- **Context:** The 2026-07-25 scan listed draft PR #106 (1Password integration)
  as "open, CI green, behind `main`". Asked to rebase it, the premise turned out
  to be gone: **#106 was closed unmerged on 2026-07-27**, and its feature landed
  instead via **#127**. Rebasing 39 commits of an already-landed feature was the
  wrong move.
- **What was actually wrong:** #127 landed #106's tree *as of commit `aa74dd6`*
  — verified by hashing: `origin/main`'s `onepassword.py`, `secrets_cli.py`, and
  `local.py` are byte-identical to `aa74dd6`. The branch had **8 further
  commits**, all hardening, and none of them reached `main`. Closing #106 dropped
  them on the floor.
- **Done:** Replayed `git diff aa74dd6..18af401` onto current `main`, scoped to
  `agent/secret_sources/onepassword.py`, `hermes_cli/env_loader.py`,
  `hermes_cli/secrets_cli.py`, `hermes_cli/main.py`, `tools/environments/local.py`
  and the three test files. Recovers 10 hardening items — the sharpest being that
  `local.py` never consulted the `_SECRET_SOURCES` registry, so a 1Password field
  such as `DATABASE_PASSWORD` was injected into `os.environ` and flowed straight
  into model-issued subprocesses; and that a *renamed* token env
  (`service_account_token_env: COMPANY_OP_TOKEN`) was unprotected because only
  the default name was blocklisted. Also: `EDITOR`/`VISUAL`/`PAGER` and the wider
  process-control blocklist, `$` → `\Z` in the env-name regex, stale-slot cache
  eviction, metadata-free errors + null-byte stripping, count-only redaction of
  two clear-text-logging sinks, relinquish-on-disable, duplicate-field-label
  safety, and a nine-subclass exception hierarchy replacing `str(exc)`.
- **Deliberately NOT ported** — #106 predates #118, so three of its hunks are
  *regressions* against today's `main`, and a naive rebase would have shipped
  them while claiming to add hardening:
  - `hermes_cli/config.py::_sanitize_env_lines` — #106 carries the
    **pre-GHSA-mv8x-fg99-32mf** line-splitting implementation. `main`'s
    strip-only version from #118 is the fix. Verified `main`'s docstring
    ("Normalize .env line endings without changing assignment semantics")
    survives untouched.
  - `pyproject.toml` — #106 says `0.15.0`; `main` is `0.18.0`. Untouched.
  - `hermes_cli/main.py` — #106 lacks `main`'s `--legacy-peer-deps` npm flag.
    Verified still present after the patch.
- **Verification:**

  - **Positive control on the headline fix:** reverting only
