### Fixed so far — two real bugs, both environment-independent

**`plugins/memory/mem0/__init__.py` — `NameError: name 'user_id'`** (3 tests,
CI-confirmed). `_start_prefetch(self, query)` computed
`effective_user_id = user_id or self._user_id`, but `user_id` is not one of its
parameters. It is a copy of the identical line in `sync_turn` fifty lines
below, where `user_id` genuinely *is* a parameter. The computed value was never
read — the closure filters via `self._read_filters()`. Deleted the line rather
than adding a parameter: nothing wanted the value.

**`hermes_cli/gateway.py` — `NameError: name 'prog_args'`** (3 tests). The
launchd plist builder assembled `core_args`, computed a `use_wrapper` flag, and
then called `prog_args.append(...)` — a name that is never assigned. All three
of `core_args`, `use_wrapper` and `prog_args` were inconsistent, so the function
could not ever have run to completion.

The surrounding comment states the intent precisely ("the wrapper execs the
python + module args we pass after it… if the wrapper is missing, fall back to
the direct-python form"), and the three failing tests assert nothing about
wrapper shape, so the comment is the spec: `prog_args` is the wrapper path in
front of `core_args` when the wrapper is usable, and `core_args` alone
otherwise.

### Not fixed — needs evidence, not a guess

**`gateway/status.py` — a duplicate definition shadowing the real one**
(14 tests, across `test_gateway_command_line_matcher.py` and
`test_scan_venv_blockers.py`).

`looks_like_gateway_command_line` was defined **twice**: at line 444, the
canonical implementation delegating to `_gateway_command_subcommand` (shlex
tokenization, profile-selector stripping, case-folding); and again at line 569
as a hand-rolled substring scan. Python keeps the last definition, so every
caller silently got the naive one. `looks_like_gateway_runtime_command_line`
was duplicated the same way.

The substring version fails exactly the cases the canonical one exists to
handle: `--profile work gateway run` (the flag splits the substring),
`--profile gateway gateway run` (the profile *value* shadows the subcommand),
bare `gateway`, and `GATEWAY RUN`. `_scan_venv_blockers`'s own docstring warns
about this in as many words — "A hand-rolled token scan here regressed
``--profile gateway gateway run``" — so the regression it describes had simply
reappeared one module over. Deleted the duplicates; the canonical definitions
were already correct and needed no change.

**`tests/hermes_cli/test_kanban_db.py` — `UnboundLocalError`** (1 test). Line
907 referenced bare `hermes_state`, but line 922 does a plain
`import hermes_state`, which makes the name function-local for the whole
function body — so the earlier reference could never resolve. The line was also
redundant: line 903 already clears that exact set via the `_hermes_state` alias.
Deleted.

**`tests/tools/test_modal_snapshot_isolation.py`** (2 tests). `modal.py` calls
`tools.lazy_deps.ensure("terminal.modal")` before touching the SDK, and that
check asks whether the *distribution* is installed — which a `sys.modules` stub
cannot satisfy. So on any machine without the real package (CI included) the
test died before reaching the snapshot logic it exists to cover. These tests
stub the entire world already (`hermes_cli`, `tools`, `tools.environments`,
`modal`); dependency resolution is one more thing to stub, not the thing under
test. Left the production check alone deliberately — it is security-adjacent,
and weakening it to accept pre-imported modules is not a change to make for a
test's convenience.
